# Lê Quốc Trạng — Portfolio

A statically exported Next.js portfolio with three complete visual styles. All styles share the profile, projects, experience, skills and education in `data/`.

| Style | URL | Direction |
| --- | --- | --- |
| Studio (default) | `/` or `/studio/` | Warm neutral colors, spacious typography, green accents |
| Pixel | `/pixel/` | Pixel font, grid background, hard borders, original SVG computer scene |
| Terminal | `/terminal/` | Monospace typography, green palette, shell-style introduction |

Use **Change the scene** to switch styles. Each style supports light, dark and system appearance. The appearance preference is saved by `next-themes`; the selected design is encoded in the URL.

## Run locally

Use Node.js 22.13+ and npm. Dependencies are pinned to stable releases and `package-lock.json` is the single lockfile.

```sh
npm ci
npm run dev
```

Open http://localhost:3000. Fonts are bundled locally through Fontsource; builds do not fetch Google Fonts.

## Validate and build

```sh
npm run typecheck
npm run build
```

`typecheck` generates Next.js types first, so it also works on a fresh checkout. The production build checks TypeScript errors and writes the static site to `out/`. Serve that directory with a static server; `next start` does not serve static exports.

For a GitHub project Pages URL, set the base path at **build time**:

```sh
NEXT_PUBLIC_BASE_PATH=/my-porfolio npm run build
```

Next.js handles internal Link URLs and imported images. `assetPath()` in `lib/assets.ts` prefixes public image paths. Do not put `/my-porfolio` directly in profile data. For a custom domain at the root, leave the environment variable empty.

## GitHub Pages

The existing site is https://lequoctrang4.github.io/my-porfolio/. The workflow in `.github/workflows/nextjs.yml` installs from the npm lockfile, typechecks, builds with the Pages base path and deploys `out/` on pushes to `main`.

Repository **Settings → Pages → Build and deployment → Source** must be **GitHub Actions** for that deployment workflow. At inspection time, the repository's Pages API reported `build_type: legacy`; that account setting has not been changed by this local update.

## Dependency migration

All retained direct dependencies and dev dependencies were checked against npm's stable `latest` tag on October 30, 2026, and pinned to those versions. Already-current packages retain their version. Notable changes:

- Next.js 15 → 16.4.3, React / React DOM → 19.3.1.
- Tailwind CSS 3 → 4.3.3 with `@tailwindcss/postcss`; the existing theme configuration is explicitly loaded. Autoprefixer is removed because Tailwind 4 handles prefixing.
- TypeScript → 7.0.2; Next.js now validates types instead of ignoring errors.
- DayPicker 8 → `@daypicker/react` 10.0.2 with the current stylesheet and component props.
- Recharts 2 → 3.10.1 with updated tooltip and legend content types.
- React Resizable Panels 2 → 4.15.2 with Group / Separator and orientation-based styling.
- Hook Form resolvers → 6, Zod → 4, Motion → 14, Sonner → 2, Lucide → 1.
- GitHub and LinkedIn SVG marks live in `components/brand-icons.tsx`, since current Lucide no longer exports those brands.
- Removed the obsolete Yarn and empty pnpm lockfiles, and the unused duplicate global stylesheet.

Official migration references: [Next.js 16](https://nextjs.org/docs/app/guides/upgrading/version-16), [Tailwind 4](https://tailwindcss.com/docs/upgrade-guide), [DayPicker 8 to 10](https://daypicker.dev/upgrading-v8-to-v10), [Recharts 3](https://github.com/recharts/recharts/wiki/3.0-migration-guide).

## Edit content

Update `data/personal-info.ts`, `data/case-studies.ts`, `data/experience.ts`, `data/capabilities.ts` and `data/education.ts`. The visible capabilities section uses evidence links instead of self-rated technology levels; `data/skills.ts` remains available for the unused interactive skills component. Visual variants live in `components/sections/hero-section.tsx` and the scoped `[data-design]` rules in `app/globals.css`. Static variant routes are generated by `app/[design]/page.tsx`.
